# The control plane for autonomous coding agents

Tariboy brings local and remote coding-agent sessions into one desktop
workspace. It starts as a familiar terminal manager and grows with the operator:

**Image → Agent → Interactive → Autopilot → Team**

- An **Image** captures an explicit plugin list and ordered prompt template.
- An **Agent** adds a durable named workspace.
- **Interactive** opens a terminal session with a human in control.
- **Autopilot** runs bounded iterations on a timer or in response to messages.
- A **Team** coordinates agents through groups and channels.

The internal alpha makes Image through Autopilot the primary path. Team,
channels, plugins, proxy policy, and complete CLI/API controls remain available
under the advanced documentation.

## What you can do in the alpha

- manage sessions on one Mac and multiple Linux servers;
- use Claude, Codex, OpenCode, or stub harness configurations;
- validate and build images from original directories containing `Tariboyfile.yaml`;
- configure Interactive and Autopilot independently;
- attach a live Console without hiding autonomous state;
- inspect triggers, current and previous iterations, usage, cost, and audit;
- pause new iterations or kill current work;
- update remote Tariboy binaries transactionally;
- export a privacy-scoped support bundle.

Start with the [ten-minute quickstart](/docs/quickstart). Before onboarding other
people, read [Security and controls](/docs/security-controls) and
[Support](/docs/support).

:::note[An ordinary terminal is a first-class use case]
`bare:latest` is an instructions-free, read-only, terminal-only image. Choose it
when you want a normal agent terminal session. It deliberately has no Autopilot
behavior and is not a general base image.
:::

## How it is built

The desktop app is a Tauri shell around the React workspace. Each managed host
runs `tariboyd`, which owns SQLite state, agents, terminals, the event loop,
AI usage, budgets, and audit. Local and remote HTTP listeners bind loopback;
remote access goes through system OpenSSH local forwarding.

For automation and deep operations, continue to [Binaries](/docs/binaries),
[Architecture](/docs/architecture), and the [Command
reference](/docs/reference/commands).
